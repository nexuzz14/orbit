# Audit UI/UX Orbit (Fase D - Langkah 1)

Dokumen ini merangkum temuan audit visual dan interaksi pada seluruh rute Web (`web/src/app/`) dan seluruh layar Aplikasi Mobile (`app/lib/features/`) sebelum penerapan sistem desain Fase D. Seluruh tangkapan layar keadaan awal (berisi data, kosong, memuat/loading, dan gagal/error pada lebar desktop maupun mobile) tersimpan di direktori `docs/design/sebelum/`.

---

## 1. Masalah Lintas Layar (Sistemik)

### 1.1 Arah Visual dan Konsistensi Warna
- **Gradasi dan Efek Berlebihan**: Pada Web (`web/src/app/globals.css`), latar mode gelap menggunakan radial-gradient kosmik serta tombol utama menggunakan gradasi neon tiga warna (`cyan-500` ke `indigo-600` ke `violet-600`) dengan bayangan berpendar (`box-shadow` berwarna). Hal ini bertentangan dengan prinsip netral-minimal dan mengurangi keterbacaan konten.
- **Nilai Warna Ditulis Langsung (Hardcoded)**: Baik di Web maupun App, kode warna heksadesimal dan kelas utilitas ditulis langsung per layar (`bg-emerald-600`, `text-rose-600`, `Colors.orange.shade50`, `Color(0xFF0EA5E9)`) tanpa melalui satu sumber design token.
- **Warna Jenis Kegiatan Tanpa Standar Tunggal**: Warna untuk jenis kegiatan (`intern`, `freelance`, `kuliah`, `pribadi`) berbeda-beda antara layar `Hari Ini`, `Jadwal`, `Tugas`, dan `Proyek`. Di beberapa tempat (seperti titik indikator pada daftar jadwal mobile), warna ditampilkan tanpa label teks pendamping.

### 1.2 Tipografi dan Keterbacaan Angka
- **Angka Nominal Tidak Rata dan Tidak Tabular**: Sebagian besar nominal uang di kartu ringkasan dan daftar transaksi belum konsisten menggunakan `tabular-nums` dan rata kanan, sehingga perbandingan nilai antarbaris sulit dipindai secara cepat.
- **Skala Tipografi Tidak Baku**: Ukuran teks menggunakan nilai acak (`text-[10px]`, `text-[11px]`, `fontSize: 11`, `fontSize: 13`) yang terlalu kecil dan menurunkan kontras keterbacaan di layar beresolusi rendah.

### 1.3 Spasi, Hierarki, dan Target Sentuh
- **Target Sentuh di Bawah 44 px**:
  - Di Web: tombol aksi ikon pada baris transaksi, kategori, akun, dan tugas berukuran `p-1` atau `p-1.5` (`24x24 px` hingga `28x28 px`), jauh di bawah batas minimum aksesibilitas `44x44 px`.
  - Di App: beberapa `IconButton` dan `ChoiceChip` padat memiliki tinggi efektif di bawah `44 px` dan spasi antar-elemen terlalu rapat (`4 px`).
- **Kepadatan Informasi Berlebihan di Atas Lipatan (Above the Fold)**: Form input diletakkan langsung di atas halaman (`Proyek`, `Anggaran`, `Tagihan`, `Tabungan`, `Akun`) sehingga mendorong daftar data utama ke bawah layar, terutama pada viewport mobile (`390x844`).

### 1.4 Penanganan Keadaan Kosong, Loading, dan Error
- **Keadaan Loading**: Hampir seluruh rute Web menampilkan teks polos `"Memuat..."` di tengah tabel atau halaman tanpa kerangka `Skeleton`, menyebabkan pergeseran tata letak (layout shift) saat data selesai dimuat. Di App digunakan `CircularProgressIndicator` tunggal tanpa struktur kerangka.
- **Keadaan Error**: Kegagalan pemanggilan kueri Supabase di Web maupun App sebagian besar diabaikan (`if (data) setItems(data)` tanpa memeriksa `error`) atau hanya menampilkan `window.alert()`. Tidak ada komponen keadaan error terstruktur dengan pesan jelas dan tombol **"Coba Lagi"**.
- **Keadaan Kosong**: Teks keadaan kosong hanya berupa satu kalimat pasif di dalam baris tabel tanpa tombol aksi langsung (CTA) untuk membuat entri pertama.
